## Primary Build Target

Use references 2 and 4 as the primary desktop command-center target. The winning view should combine the lane-based release pipeline from reference 2 with the high-impact Signal Atlas from reference 4.

Required qualities:

- Dense enterprise information architecture with clear hierarchy.
- Graphite shell, warm steel dividers, electric teal signal flow, and amber risk gates.
- Left navigation, top search/context controls, right MCP activity/risk rail, and dominant center visualization.
- Stage-oriented release pipeline with visible Ingest, Process, Enrich, Risk Gate, Approve, Release, and Monitor progression.
- Live MCP activity that feels audit-safe and operational, not decorative.

## Reviewer Target

Use reference 1 for the approval workflow. The reviewer mode must show a prioritized queue, selected workflow details, risk gate checklist, release packet summary, MCP activity, and bottom action bar for request changes, save, and approve/release.

The bottom action bar is important for demo clarity because it gives judges a visible human-in-the-loop control point.

## Copilot Target

Use reference 3 for the Microsoft 365 Copilot Chat proof. The left side should feel like Copilot Chat, and the right side should show Signal Foundry as the connected agent/workbench with proposed workflow, risk gates, MCP trace, release pipeline, release packet, and audit evidence.

This screen must prove that Signal Foundry is not just a standalone dashboard. It is a Copilot-centered agent experience with the command center as evidence and control.

## Light Variant Target

Use reference 5 only as a fallback or secondary executive view. The dark command center is the primary hackathon visual, but the light view can support screen sharing, slide screenshots, or judge walkthroughs where readability is more important than drama.

## Implementation Guardrails

- Do not turn these into generic metric-card dashboards.
- Do not render raw Microsoft 365 content, private user activity, secrets, tokens, or production customer data.
- Keep labels concise and operational.
- Every risk, approval, release, and MCP event must be tied to a synthetic record and correlation ID.
- Use generated visual polish through layout, motion, signal paths, and information design rather than stock images or fake AI illustrations.
- Text must fit in all buttons, nav items, cards, lanes, and rails at desktop, tablet, and mobile widths.

## Screenshot Acceptance Criteria

- Desktop command center resembles references 2 and 4 in layout density, nav structure, palette, and signal visualization.
- Reviewer workflow resembles reference 1 with visible queue, checklist, release packet, and approval bar.
- Copilot proof resembles reference 3 closely enough that judges understand where Copilot Chat ends and Signal Foundry begins.
- Light variant resembles reference 5 when enabled, without becoming the default visual direction.
- No screenshot includes secrets, raw source content, tokens, real PII, or production data.
